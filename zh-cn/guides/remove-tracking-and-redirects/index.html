如何移除 UTM 标签并还原重定向链接

添加到 Chrome——免费

简短回答：在 Link Extractor 中打开 过滤和设置，再打开 移除 utm 等跟踪参数。重定向链接已经显示为它们的真实地址：显示真实网址而非重定向 默认就是开启的。两者都会作用于列表、你复制的内容和 CSV。

两个不同的问题

跟踪标签是加在地址后面用来统计点击的参数： https://shop.example/item?utm_source=newsletter&fbclid=…。带不带这些参数，页面都是同一个，但在电子表格里，带标签的副本看起来像不同的链接，会让你的列表变长。

重定向链接把真实地址包在另一个地址里： https://www.google.com/url?q=https://example.com/ 或 https://l.facebook.com/l.php?u=…。原样复制的话，每一行都以 google.com 或 facebook.com 开头，你就没法按它们指向的网站来排序或过滤。

操作步骤

  1. 打开网页，点击 Link Extractor 图标（Alt+Shift+L，Mac 上是 Ctrl+Shift+L）。
  2. 打开 过滤和设置。
  3. 在 复制和文件 下，打开 移除 utm 等跟踪参数。让 显示真实网址而非重定向 保持开启。
  4. 检查列表：侧边栏会提示 已从网址中移除 utm 等跟踪参数，并显示有多少重定向链接展示的是真实网址。每个这样的链接都标有 来自重定向；把鼠标悬停在标记上，可以看到页面上的原始地址。
  5. 点击 复制网址 或 CSV。

这些设置会被记住，用于之后的网页。

会移除哪些标签

所有 utm_… 参数，以及 fbclid、gclid、 dclid、gbraid、wbraid、msclkid、 yclid、ysclid、igshid、mc_cid、 mc_eid、_hsenc、_hsmi、mkt_tok、 twclid、ttclid、li_fat_id、srsltid、 _ga 和 _gl。

这个列表是有意设得很短的。ref、source 或 id 这样的参数会保留，因为有些网站需要它们，移除后链接会失效。地址的其余部分原样保留：参数的顺序、编码，以及 # 之后的部分。仅因跟踪标签而不同的链接会合并为一行。

会还原哪些重定向链接

Google（/url?q=）、Bing（/ck/a）、DuckDuckGo、Facebook 和 Instagram 的外链、YouTube、LinkedIn 和 Reddit 的重定向、Outlook 安全链接、Slack、Steam 和 VK。真实地址是直接从链接本身读出来的：不会打开任何页面，也不会发出任何请求，所以既快又保护隐私。

在 CSV 中，url 列是真实地址，original_url 保留被包装的地址。如果想让链接保持页面上的原样，请关闭 显示真实网址而非重定向。

它做不到什么

  • bit.ly 或 t.co 这样的短链接，目标地址存放在它们自己的服务器上。要找到它就得打开链接，而 Link Extractor 不发出任何网络请求，所以它们保持原样。这类链接请使用网址展开工具。
  • 有些 Google 搜索结果隐藏了真实地址。这时链接里只有一个看不出含义的 Google 代码。侧边栏会把这样的行标为 Google 隐藏了网址，并按 Google 给出的样子复制，而不是去猜。在结果页上，只看结果 只列出搜索结果，按顺序排列，不含广告。
  • 包装着 javascript: 或 data: 地址的链接，绝不会被还原成那个地址：它保持包装链接的样子。

常见问题

移除标签会改变网页吗？

不会。改变的只有列表、复制内容和文件。网页及其链接保持原样。

为什么移除标签默认是关闭的？

这样默认得到的就是页面上原原本本的链接。有些人需要这些标签，例如检查某个推广活动的链接。一个开关就能打开它。

能看出哪些链接是重定向吗？

能。它们在列表中带有 来自重定向 标记，在 CSV 中，它们的原始地址在 original_url 列里。
